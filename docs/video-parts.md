# Demo video in 8 short parts (~3:40 total)

**How to stay predictable:** first do the live runs (takes in demo-script.md) with no pressure.
Then record each part as its own short clip **over the finished chat**, scrolling slowly while
you talk. The agents are already done, so nothing can break on camera.
Record with Win+Alt+R (turn the mic on with Win+Alt+M). Join the parts in Clipchamp.

## Part 3 · Voice pitch → a new room (30 s)
**Show:** #jam-room: your spoken pitch, the designer's plan, `approve`, the new channel
appearing in the sidebar, the link in the lobby.
**Say:**
"I just say my idea out loud with Wispr Flow. The designer turns it into a short plan. When I
reply approve, the designer uses a Switch room template to create a new Discord channel just for
this game, with the agents already inside. Then it posts the link back in the lobby. One game,
one room."

## Part 4 · Build → playtest handoff (30 s)
**Show:** the game room: builder's messages, the `@tester` handoff, PASS with checks, the GIF.
**Say:**
"The builder writes the game. When it's done, it mentions the tester. Switch delivers that
message and wakes up the Codex playtester. The tester plays the game in a real browser, checks
every rule from the plan, and posts a PASS with a GIF of its own test run, sent through Switch
right into Discord."

## Part 5 · Human approval → phone (20 s)
**Show:** the "Permission needed" card, tap Allow, the live link, then the phone clip.
**Say:**
"The game can't go public on its own. Switch shows a permission card in Discord, and only an
approver can answer it. I tap Allow, the game goes live, and my friends play it on their phones."

## Part 6 · Friends join in, Switch keeps the rules (30 s)
**Show:** friend asks for a change → v2 live → arcade card with both names. Then friend's
`@builder ship it` → Switch's refusal. Then the explain answer.
**Say:**
"My friend asks for a change, I approve, and it becomes version two, with both of us credited,
because Switch tells the agents who really sent each message. When someone who isn't an approver
tells the builder to ship, Switch blocks it before the agent even sees it. But anyone can ask the
designer how the game works. Great for kids learning to code."

## Part 7 · Bug → hotfix, caught on camera (30 s)
**Show:** phone screenshot (scooter on the sidewalk), the bug message, ❌ GIF, the fix,
the side-by-side GIF, the bug hunter badge.
**Say:**
"My friend found a bug: the scooter rides off the road. They send a screenshot to the tester.
The tester turns it into a saved test and shows it failing in a GIF. The builder fixes it, and
the tester posts the same moves on the old and new version, side by side. My friend gets a bug
hunter badge, and this test runs again on every future version."

## Part 8 · Arcade, proof, close (30 s)
**Show:** arcade → Comet Dash "remix of" → its "How this game was made" page →
docs/SWITCH_FEATURES.md on GitHub → terminal `npm run verify` ending in PASS → arcade + repo URL.
**Say:**

AI companies in one room. This table maps every Switch feature to the code, and one command,
npm run verify, checks it all. Built by voice with Wispr Flow. This is Jam Room. Go make a game
with your friends."
